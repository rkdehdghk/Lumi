# Lumi 제품 발표 자료 패키지 — 설계 명세서

**작성일**: 2026-08-02
**대상**: 현업 개발자/기술자
**목적**: 제품 소개 발표 (고객 설득)
**접근법**: 옵션 B — "독창성으로 승부" (공감 → 차별 → 근거 → 체험 → 행동)

---

## 1. 프로젝트 개요

### 1-1. 목표
Lumi(루미) 언어와 Lumina IDE를 현업 개발자/기술자에게 소개·설득하는 제품 발표 자료 패키지를 제작한다. 현업 개발자는 가장 회의적인 청중("또 자작 언어야?")이므로, 기술력 자랑이 아닌 **"공감에서 출발해 차별점을 보여주고, 그것이 견고한 C 구현 위에 세워졌음을 증명하며, 직접 써보라로 마무리하는"** 설득 아크를 채택한다.

### 1-2. 핵심 메시지 아크 (옵션 B, 6단계)
1. **공감** — 현업 개발자의 일상적 고통 (예외 장황함·경로 이스케이프·인자 순서 불일치)
2. **정체성** — Lumi가 무엇인지 한 줄 ("파이썬처럼 읽고, C처럼 다루는 언어")
3. **차별** — 독창 기능 4종 (`safe` 예외 / Raw 경로 / 인자 통일 / 시퀀스 패밀리)
4. **근거** — C 구현의 깊이 (직접 구현한 런타임, 15,000줄)
5. **체험** — 라이브 데모
6. **행동** — 로드맵·시작하기

### 1-3. 성공 기준
- 현업 개발자가 "왜 쓰는지"를 납득할 수 있을 것 (단순 기술 자랑이 아님)
- 발표 후 링크/자료를 통해 직접 탐색·설치까지 유도될 것
- 15-20분 발표 분량에 맞춰 슬라이드 18장이 시간 내에 소화될 것

## 3. 산출물 1: 슬라이드 덱 상세 구성 (18장)

표준 15-20분 발표용. 각 장은 **헤드라인 + 본문(슬라이드에 뜨는 내용) + 발표자 멘트(말로 설명)** 구조.

### 액트 1: 공감 — 현업 개발자의 고통 (Slide 1-3)

#### Slide 1 — 오프닝 / 타이틀
- **헤드라인**: Lumi — 생각의 순서대로 적는 언어
- **본문**: 부제 "언어·인터프리터·IDE까지, 모두 직접 만든" / 발표자·날짜
- **멘트**: 자기소개 + "오늘은 제가 만든 언어를 소개하겠다" 한 줄 후킹

#### Slide 2 — 고통 1: 예외 처리의 장황함
- **헤드라인**: try-catch 하나에도 보일러플레이트가 필요합니다
- **본문**: 파이썬 코드 조각 (성공 로직과 에러 로직이 뒤섞인 전형적 패턴)
- **멘트**: "성공했을 때만 실행하고 싶은 코드, 여러분은 어디에 둡니까?" → `if not error:` 패턴의 어색함 지적

#### Slide 3 — 고통 2: 경로 이스케이프 + 인자 순서 불일치
- **헤드라인**: 매일 겪는 두 번째 고통
- **본문**: 좌 `read("C:\\notes\\new.txt")` (역슬래시 두 번), 우 `sort(reverse=True, ...)` vs `replace(old, new, ...)` (언어마다 인자 순서 제각각)
- **멘트**: "이건 버그가 아니라 설계입니다. 하지만 매번 고통스럽죠."

### 액트 2: 정체성 — Lumi가 무엇인지 (Slide 4-5)

#### Slide 4 — Lumi 한 줄 정의
- **헤드라인**: Lumi(루미): 파이썬처럼 읽고, C처럼 다루는 언어
- **본문**: 3가지 핵심 속성 카드 — (1) 세미콜론 없는 들여쓰기 문법 (2) 한국어 친화 설계 (3) 언어+인터프리터(C)+IDE(C++/Qt6) 올인원 자작
- **멘트**: "이 고통들을 해결하려고 직접 만든 언어가 Lumi입니다."

#### Slide 5 — 전체 그림: 아키텍처
- **헤드라인**: 언어 하나를 통째로 만들었습니다
- **본문**: 3계층 다이어그램 — [Lumina IDE / C++17·Qt6] → [Lumi 인터프리터 / 순수 C] → [.lumi 코드], 각 층에 핵심 수치(15,000줄, 46 예제)
- **멘트**: "언어 설계부터 런타임까지 모두 제 손으로 구현했습니다."

### 액트 3: 차별 — 독창 기능 4종 (Slide 6-11, 핵심)

#### Slide 6 — 차별 1: `try / safe / catch / always`
- **헤드라인**: "성공했을 때만"을 언어가 지원합니다
- **본문**: Lumi 코드 (`try:` → `safe:` 성공시 → `catch:` 실패시 → `always:` 항상) vs 동등한 파이썬 코드 (`if not error:` 꼼수 또는 중첩)
- **멘트**: 고통 1번의 해법. "`safe` 블록 하나로 성공 로직을 깔끔하게 분리합니다."

#### Slide 7 — 차별 2: 작은따옴표 Raw 경로
- **헤드라인**: `'C:\notes\new.txt'` — 역슬래시를 두 번 쓰지 마세요
- **본문**: 큰따옴표(글자용, 이스케이프) vs 작은따옴표(경로용, Raw) 규칙 + 코드 비교
- **멘트**: 고통 2번의 해법. "윈도우 경로를 그대로 붙여넣기만 하면 됩니다."

#### Slide 8 — 차별 3: "수식어 앞, 대상 마지막" 통일 원칙
- **헤드라인**: 함수 하나를 배우면, 나머지는 무료로 배웁니다
- **본문**: 규칙 설명 + 5개 함수 인자 순서 일관성 표 (`sort(방향, 시퀀스)` / `replace(바꿀것, 새것, 문자열)` / `upper(자리, 문자열)` 등)
- **멘트**: 고통 3번의 해법. "인자 순서를 외울 필요가 없습니다. 읽는 순서 그대로입니다."

#### Slide 9 — 차별 4: 시퀀스 패밀리 (Sequence Family)
- **헤드라인**: 리스트·튜플·문자열·바이트가 한 가족입니다
- **본문**: 4개 자료형이 공유하는 연산 표 (`in`, `+`, `*`, `len`, 인덱싱, 슬라이싱, `sort`, `shuffle`) + 코드 예시
- **멘트**: "문자열도 리스트처럼 다루고, 바이트도 같은 연산으로 다룹니다."

#### Slide 10 — 보너스: 일관성의 연장선들
- **헤드라인**: 철학이 문법 곳곳에 스며 있습니다
- **본문**: 콤팩트 카드 — C스타일 for문(쉼표 구분) / `use` 자동 닫기 / `bring` 임포트 / 2진·16진 리터럴 / 자료형 선언
- **멘트**: "일관성이 언어 전체로 퍼져 있습니다."

#### Slide 11 — 철학 요약
- **헤드라인**: "적는 사람끼리의 약속"을 언어가 받아들입니다
- **본문**: 3가지 설계 원칙 — 일관된 규칙 / 한국어 친화 / 친절한 오류 메시지(`[line N]` 줄 안내)
- **멘트**: 다음 액트(구현 깊이)로 넘어가는 다리. "이런 철학이 그냥 말로만이 아닙니다. 직접 구현한 런타임 위에 세워졌습니다."

### 액트 4: 근거 — C 구현의 깊이 (Slide 12-14)

#### Slide 12 — 인터프리터 아키텍처
- **헤드라인**: 순수 C로 직접 구현한 런타임
- **본문**: 파이프라인 다이어그램 — Lexer → Parser → [Tree-walk interp + Bytecode VM 듀얼 모드], 핵심 파일(`lexer.c`/`parser.c`/`interp.c`/`value.c`/`vm.c`), 총 약 7,300줄
- **멘트**: "외부 라이브러리 없이, 렉서부터 VM까지 모두 C로 짰습니다."

#### Slide 13 — 직접 구현한 핵심 기술
- **헤드라인**: GC, 문자열, 딕셔너리까지 직접
- **본문**: 3개 하이라이트 카드 — (1) 참조 카운팅 GC (2) UTF-32 코드포인트 문자열 (3) 순서 보장 해시 딕셔너리. 듀얼 실행 모드(VM 우선 → tree-walk 폴백) 언급
- **멘트**: "이것들이 Lumi의 일관성을 가능하게 하는 엔지니어링 기반입니다."

#### Slide 14 — 규모와 성숙도
- **헤드라인**: 프로토타입이 아닙니다
- **본문**: 수치 카드 — 15,000줄 핵심 코드 / 46개 예제 / 544줄 그래프 알고리즘 라이브러리 / 자동화 테스트 23종 / Qt6 IDE
- **멘트**: "복잡한 알고리즘을 소화하는 수준입니다. 데모로 보여드리겠습니다."

### 액트 5: 체험 — 라이브 데모 (Slide 15-16)

#### Slide 15 — 데모 안내
- **헤드라인**: 직접 보여드리겠습니다
- **본문**: 데모 동선 체크리스트 — (1) IDE 실행·F5 (2) 한국어 변수+input (3) 시퀀스 패밀리 (4) `safe` 예외 (5) 객체지향 연산자 재정의 (`v1 + v2`)
- **멘트**: 라이브 코딩 전환. "화면 보시죠."

#### Slide 16 — 데모 하이라이트 (데모 후 정리용)
- **헤드라인**: 방금 본 것들
- **본문**: 데모에서 보여준 핵심 코드 스니펫 재노출 + 각각이 왜 의미 있는지 한 줄 캡션
- **멘트**: "이것들이 한 IDE 안에서, F5 한 번에 돌아갑니다."

### 액트 6: 행동 — 로드맵·시작하기 (Slide 17-18)

#### Slide 17 — 로드맵 & 한계의 솔직함
- **헤드라인**: 지금은 여기까지, 다음은 명확합니다
- **본문**: 좌 "이미 완성된 것"(코어 문법·OOP·예외·IDE) / 우 "다음 단계"(HTTP/네트워크, 비동기, 패키지 관리, LSP/디버거)
- **멘트**: "현재 한계를 솔직히 말씀드립니다. 그만큼 방향이 명확합니다."

#### Slide 18 — 마무리 & 시작하기
- **헤드라인**: 설치 없이, 더블클릭 한 번이면 시작합니다
- **본문**: CTA 3종 — (1) 다운로드/저장소 링크 (2) 사용설명서 링크 (3) 연락처. 핵심 슬로건 재강조
- **멘트**: "감사합니다. 직접 써보시고 피드백 주세요."

## 5. 산출물 3: 원페이저 구성 (onepager.md)

A4 1-2장 분량. 의사결정자(또는 바쁜 기술 리더)가 **3분 만에** 파악 가능해야 함. 스토리텔링과 긴 코드는 빼고, **핵심 사실과 수치**만 남김.

## 6. 핵심 메시지 소재 (공통 활용)

모든 산출물에서 일관되게 인용할 핵심 사실. (README·사용설명서·소스코드 분석에서 추출)

### 6-1. 핵심 슬로건
- 메인: **"Lumi — 생각의 순서대로 적는 언어"**
- 부제: **"파이썬처럼 읽고, C처럼 다루는, 내가 만든 언어"**
- CTA: **"설치 없이, 더블클릭 한 번이면 시작합니다"**

### 6-2. 차별점 4종 (모든 산출물의 중심)
1. **`try / safe / catch / always` 예외 처리** — `safe` 블록으로 "성공 시에만" 실행하는 코드를 분리. 다른 언어의 `if not error:` 꼼수나 중첩 try 없이 표현.
2. **작은따옴표 Raw 경로** — `'C:\notes\new.txt'` 역슬래시 두 번 쓰지 않음. 큰따옴표는 글자·문장(이스케이프), 작은따옴표는 경로(Raw)로 역할 분담.
3. **"수식어 앞, 대상 마지막" 인자 통일 원칙** — `sort(방향, 시퀀스)`, `replace(바꿀것, 새것, 문자열)`, `upper(자리, 문자열)`. 한 함수의 규칙을 배우면 나머지가 무료로 익혀짐.
4. **시퀀스 패밀리** — 리스트·튜플·문자열·바이트가 `in`, `+`, `*`, `len`, 인덱싱, 슬라이싱, `sort`, `shuffle`을 공유.

### 6-3. 기술 근거 수치
- 핵심 코드 약 **15,000줄** (인터프리터 C 약 7,300줄 + IDE C++ 약 4,600줄 + builtins 2,900줄)
- 인터프리터: **순수 C17**, tree-walk + 바이트코드 VM **듀얼 실행 모드**
- 직접 구현: **참조 카운팅 GC**, **UTF-32 코드포인트 문자열**, **순서 보장 해시 딕셔너리**
- IDE: **C++17 / Qt6 Widgets** (Electron에서 Qt로 전면 재작성)
- 예제 **46개** + 자동화 테스트 **23종**
- 대표 예제: **544줄 그래프 알고리즘 라이브러리** (다익스트라/벨만-포드/Floyd-Warshall/Prim/Kruskal/Union-Find/위상정렬)

### 6-4. 데모용 코드 예시 (슬라이드·웹·원페이저 공통 활용)
- 예외 `safe`: `try: ... safe: print("성공") catch e: ... always: ...`
- Raw 경로: `read('C:\notes\new.txt')`
- 시퀀스: `[1,2] + [3,4]`, `"ab" * 3`, `"e" in "hello"`
- OOP 연산자 재정의: `v1 + v2` 가 `add()` 메서드 호출 → `Vector(3, 7)`
- 한국어 변수: `val 이름 = input("이름이 뭐예요? ")`

### 6-5. 로드맵 (솔직한 한계)
- **완성**: 코어 문법·객체지향(상속/다형성/연산자재정의)·예외 처리·IDE·파일 I/O·시간 API·JSON
- **다음 단계**: HTTP/네트워킹, 비동기/동시성, 서드파티 패키지 관리, LSP/디버거

## 7. HTML 슬라이드 기술 명세 (slides.html)

- **상호작용**: 화살표 키 탐색, `S` 키 발표자 노트 뷰(reveal.js Speaker View) 활성화 (발표자 멘트는 `<aside class="notes">`에 배치)
