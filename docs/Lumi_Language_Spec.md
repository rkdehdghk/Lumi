# Lumi 언어 명세 (Language Specification)

**판: 0.9.0** · 마지막 갱신: 2026-08-09

---

## 0. 이 문서에 대하여

이 문서는 Lumi 를 **다시 구현할 수 있을 만큼** 적어 둔 것입니다. 사용법을 배우려면 [`Lumi 사용설명서.md`](../Lumi%20사용설명서.md) 를 보세요 — 그쪽이 예제와 설명이 훨씬 많습니다. 여기는 "정확히 무엇이 허용되고, 무엇이 어떻게 도는가"만 적습니다.

**한 가지 원칙**: 이 문서와 `c-interpreter/src/` 의 코드가 어긋나면 **코드가 맞습니다.** 그러면 이 문서가 버그입니다. 명세가 구현보다 앞서 나가면 아무도 안 믿게 되므로, 여기 적힌 것은 전부 파서·인터프리터에서 그대로 옮긴 것입니다.

| 무엇이 | 어디에 |
|---|---|
| 어휘 규칙 | `src/lexer.c` |
| 문법 | `src/parser.c` |
| 시맨틱 | `src/interp.c`, `src/builtins.inc`, `src/value.c` |
| 내장 이름 목록 | `src/lumiwords.h` (**한 곳뿐입니다**) |

## 1. 표기법

EBNF 는 이렇게 씁니다.

| 적기 | 뜻 |
|---|---|
| `"글자"` | 있는 그대로의 글자 |
| `A B` | A 다음에 B |
| `A \| B` | A 이거나 B |
| `[ A ]` | A 는 있어도 되고 없어도 됨 |
| `{ A }` | A 를 0 번 이상 |
| `( A )` | 묶기 |
| `NAME` | 대문자는 어휘 토큰 (2 장) |

## 2. 어휘 구조 (Lexical Structure)

### 2.1 글자와 인코딩

소스 파일은 **UTF-8** 입니다. 맨 앞의 BOM 은 읽을 때 버립니다. 이름과 글자값에 한글을 비롯한 모든 유니코드 글자를 쓸 수 있습니다.

글자값(문자열)은 안에서 **UTF-32 코드포인트 배열**로 다룹니다. 그래서 `len("한글")` 은 바이트 수 6 이 아니라 글자 수 **2** 이고, `"가나다"[1]` 은 `"나"` 입니다.

### 2.2 줄과 들여쓰기 (Off-side Rule)

블록은 중괄호가 아니라 **들여쓰기**로 묶습니다.

- 탭 하나는 **4칸**으로 셉니다.
- 어떤 줄의 칸 수가 앞줄보다 크면 `INDENT`, 작으면 그만큼 `DEDENT` 를 냅니다.
- 줄여서 내려온 칸 수가 예전에 쓰던 어떤 칸 수와도 맞지 않으면 오류입니다 (`Indentation does not match`).
- **빈 줄과 주석뿐인 줄은 들여쓰기 계산에서 뺍니다.** 블록 가운데 아무 칸에나 주석을 둘 수 있습니다.
- **괄호 `( ) [ ] { }` 안에서는 줄바꿈이 무시됩니다.** 그래서 여러 줄에 걸쳐 리스트·딕셔너리·인자 목록을 적을 수 있습니다.
- 들여쓰기는 256 단계까지입니다.

### 2.3 주석

```
// 줄 끝까지
/. 열고 닫는 주석. 여러 줄에 걸쳐도 됩니다 ./
```

`/.` 를 열고 `./` 로 닫지 않으면 오류입니다. 여는 주석은 식 가운데에도 올 수 있습니다 — `print(1 /. 가운데 ./ + 2)` 는 `print(1 + 2)` 와 같습니다.

### 2.4 예약어 (Reserved Words)

37 개입니다. 변수·함수·클래스 이름으로 쓸 수 없습니다.

```
val     if      elif    else    while   func    return
true    false   none    and     or      not     print
bring   up      for     in      break   continue
global  local   switch  case    default
class   from    this    super   use     abstract
try     catch   safe    always  error   test
```

**자료형 이름 12 개**는 예약어가 *아닙니다*. 뒤에 이름이 오면 선언으로 읽고, 아니면 보통 함수 호출(형 변환)입니다.

```
int  float  num  char  str  text  seq  bytes      (값을 다듬어 담습니다)
bool list  tuple dict                             (맞는지 보기만 합니다)
```

같은 12 개를 함수의 매개변수·반환 자료형으로도 씁니다 (4.1 절 `func_stmt`).

> **주의** — 예약어가 아닌 **내장 함수 이름**(`len`, `sort`, `shell` …)은 문법상 다시 정의할 수 있지만, 부를 때는 **내장이 먼저 잡힙니다** (5.2 절). `lumi lint` 가 이것을 경고합니다.

### 2.5 이름 (Identifiers)

```
IDENT = (letter | "_") { letter | digit | "_" }
```

`letter` 에는 ASCII 글자와 **0x80 이상의 모든 바이트**가 들어갑니다 — 즉 한글·한자·이모지가 다 됩니다. 숫자로 시작할 수는 없습니다.

### 2.6 숫자 (Number Literals)

```
NUMBER = decimal | binary | hex
decimal = digit { digit } [ "." digit { digit } ]
binary  = "0b" | "0B" , bit { bit }
hex     = "0x" | "0X" , hexdigit { hexdigit }
```

- 점이 있으면 **실수**(IEEE 754 배정밀도), 없으면 **정수**(부호 있는 64 비트).
- 점은 한 번만 올 수 있습니다.
- `0b`/`0x` 뒤에는 자릿수가 하나 이상 있어야 하고, **점을 붙일 수 없습니다.**
- 십진 정수가 `9223372036854775807` 을 넘으면 읽을 때 오류입니다.
- 자릿수 사이 구분 기호(`1_000` 같은 것)는 **없습니다.**

### 2.7 글자값 (String Literals)

```
STRING  = '"' { char | escape } '"'  |  "'" { char } "'"
FSTRING = "$" STRING
```

- **큰따옴표** `"..."` — 이스케이프를 해석합니다.
- **작은따옴표** `'...'` — **날글자(raw)** 입니다. `\` 를 그대로 둡니다. 윈도우 경로에 씁니다: `'C:\사진\개.png'`.
- 글자값은 여러 줄에 걸칠 수 있습니다 (줄바꿈이 그대로 들어갑니다).

이스케이프:

| 적기 | 뜻 | | 적기 | 뜻 |
|---|---|---|---|---|
| `\n` | 줄바꿈 | | `\e` | 이스케이프(27) |
| `\t` | 탭 | | `\"` `\'` `\\` | 그 글자 그대로 |
| `\r` | 줄 맨 앞 | | `\xNN` | 16진 두 자리 |
| `\a` | 삑 소리 | | `\uXXXX` | 16진 네 자리 |
| `\b` | 한 칸 뒤로 | | `\UXXXXXXXX` | 16진 여덟 자리 |
| `\f` | 다음 쪽 | | | |
| `\v` | 세로 탭 | | | |

- `\x` `\u` `\U` 는 자릿수가 모자라면 오류이고, 값이 **0 이거나 0x10FFFF 를 넘으면** 오류입니다 (0 을 넣으면 출력이 거기서 잘리기 때문입니다).
- **모르는 이스케이프는 역슬래시를 그대로 둡니다.** `"C:\사진"` 은 `C:\사진` 입니다 (파이썬과 같은 규칙).

**f-string** `$"..."` 은 `{` `}` 안의 것을 식으로 읽어 값을 끼워 넣습니다. `{{` 와 `}}` 는 중괄호 한 개를 뜻합니다. 중괄호는 겹쳐 쓸 수 있습니다.

### 2.8 연산자와 기호

```
세 글자: **=  <<=  >>=
두 글자: ==  !=  <=  >=  &&  ||  **  <<  >>
         +=  -=  *=  /=  %=  &=  |=  ^=  ++  --  ?.  ??
한 글자: + - * / % ( ) < > = , : ! [ ] { } & | ^ ~ .
```

### 2.9 세미콜론

**쓰지 않습니다.** `;` 가 나오면 오류로 알려 줍니다. 한 줄에 한 문장입니다.

## 3. 프로그램 구조

```ebnf
program   = { NEWLINE | statement } EOF
block     = ":" NEWLINE INDENT statement { statement } DEDENT
```

블록은 **비어 있을 수 없습니다** — 문장이 하나 이상 있어야 합니다.

문장은 `NEWLINE`, `DEDENT`, `EOF` 중 하나로 끝나야 합니다. 그 밖의 것이 남아 있으면 `Unexpected token at end of statement` 오류입니다.

## 4. 문법 (Grammar)

### 4.1 문장

```ebnf
statement = let_stmt    | typed_decl  | if_stmt     | while_stmt
          | switch_stmt | for_stmt    | func_stmt   | class_stmt
          | return_stmt | "break"     | "continue"
          | use_stmt    | try_stmt    | error_stmt  | test_stmt
          | bring_stmt  | scoped_stmt | expr_stmt
```

#### 값 만들기

```ebnf
let_stmt    = "val" ( IDENT "=" expression
                    | ( "(" | "[" ) IDENT { "," IDENT } ( ")" | "]" ) "=" expression )
scoped_stmt = ( "global" | "local" ) IDENT "=" expression
```

두 번째 꼴은 **구조 분해**입니다: `val (a, b) = 점()` / `val [x, y] = 목록`. 여는 괄호와 닫는 괄호의 짝이 맞아야 합니다.

```ebnf
typed_decl  = TYPE_NAME ( names_only | names_eq_values | one_by_one )
names_only      = IDENT { "," IDENT }                        (* 자료형의 기본값 *)
names_eq_values = IDENT { "," IDENT } "=" expression { "," expression }
one_by_one      = IDENT "=" expression { "," IDENT "=" expression }
```

어느 꼴인지는 **괄호 밖 `=` 의 개수**로 가릅니다: 0 개면 기본값, 1 개면 이름들과 값들을 차례로 짝짓고(개수가 다르면 오류), 2 개 이상이면 이름마다 따로 적은 것입니다.

`TYPE_NAME IDENT` 가 선언으로 읽히는 조건은, 그 뒤가 **줄 끝이거나 `=` 또는 `,`** 일 때뿐입니다. 그래서 `int x` 는 선언이지만 `int(x)` 는 형 변환 호출입니다.

#### 흐름 바꾸기

```ebnf
if_stmt     = "if" expression block { "elif" expression block } [ "else" block ]
while_stmt  = "while" expression block
switch_stmt = "switch" expression ":" NEWLINE INDENT
                { "case" expression { "," expression } block | "default" block }
              DEDENT
return_stmt = "return" [ expression ]
```

`switch` 안에는 `case` 와 `default` 만 올 수 있고, `default` 는 **하나뿐**입니다 (어느 자리에 두어도 됩니다).

```ebnf
for_stmt = "for" IDENT "in" expression block          (* 하나씩 꺼내며 *)
         | "for" for_part "," expression "," for_part block   (* C 식 *)

for_part = "val" IDENT "=" expression
         | typed_decl_one
         | ( "++" | "--" ) postfix
         | IDENT "=" expression
         | expression [ "++" | "--" | compound_op expression ]
```

어느 쪽인지는 이렇게 가릅니다: `for` 다음이 `val` 이면 C 식, 이름 뒤에 `in` 이 오면 하나씩 꺼내는 쪽, 그 밖이면 C 식입니다. `for val x in ...` 처럼 적으면 `val` 을 그냥 건너뜁니다.

#### 함수와 클래스

```ebnf
func_stmt = [ "abstract" ] "func" IDENT "(" [ params ] ")" [ TYPE_NAME ]
            ( block | ":" NEWLINE )
params    = param { "," param }
param     = [ TYPE_NAME ] IDENT [ "=" expression ]

class_stmt = "class" IDENT [ "from" IDENT ] ":" NEWLINE INDENT
               { func_stmt | let_stmt | typed_decl }
             DEDENT
```

- **기본값이 있는 매개변수는 뒤쪽에 몰아야 합니다.** 앞에 기본값이 있고 뒤에 없으면 오류입니다.
- **자료형은 골라서 적습니다.** 매개변수 앞의 `TYPE_NAME` 과 `)` 뒤의 `TYPE_NAME` 은 둘 다 선택입니다. 안 적은 자리는 아무 값이나 오갑니다.
  `TYPE_NAME IDENT` 로 읽히려면 자료형 이름 **바로 뒤가 이름**이어야 합니다 — 그래서 `f(int(x))` 는 형 변환 호출 그대로입니다.
  적어 두면 **부를 때**(인자를 자리에 놓은 뒤, 기본값 포함)와 **끝날 때**(돌려주는 값) `typed_decl` 과 **똑같은 규칙**으로 검사합니다.
- `abstract` 함수는 몸통이 없습니다.
- 클래스 안에는 메서드와 공유 값만 올 수 있습니다. **같은 이름의 메서드를 두 번 적으면 오류입니다.**
- 이름 있는 함수는 문장이고, `func` 뒤에 바로 `:` 나 `,` 가 오면 "이름 없는 함수는 값이니 어딘가에 담으라"는 오류를 냅니다.

#### 그 밖

```ebnf
use_stmt   = "use" IDENT "=" expression block
try_stmt   = "try" block { catch_clause | "safe" block | "always" block }
catch_clause = "catch" [ IDENT [ IDENT ] ] block
error_stmt = "error" "(" expression [ "," expression ] ")"
test_stmt  = "test" STRING block
bring_stmt = "bring" [ IDENT "=" ] ( IDENT | STRING ) [ "up" IDENT { "," IDENT } ]
expr_stmt  = expression [ ( "=" | compound_op ) expression | "++" | "--" ]
           | ( "++" | "--" ) postfix
```

- `catch` 뒤 이름이 **하나뿐일 때는 첫 글자가 대문자면 오류 종류**, 아니면 **담을 변수**로 봅니다 (클래스 이름을 대문자로 짓는 관습을 그대로 씁니다). 둘이면 `종류 변수` 순서입니다.
- `catch` 는 여러 개 둘 수 있고 **앞에서부터 처음 맞는 하나만** 돕니다. `safe` 와 `always` 는 각각 하나씩입니다.
- `error(값)` 이면 메시지만, `error(종류, 값)` 이면 종류와 메시지입니다.
- `bring ... up` 뒤에는 이름이 하나 이상 있어야 합니다.
- 대입의 왼쪽이 될 수 있는 것은 **변수 이름 / `[]` 로 꺼낸 자리 / `.` 로 꺼낸 자리** 셋뿐입니다.

`compound_op` 은 11 개입니다: `+= -= *= /= %= **= &= |= ^= <<= >>=`. 전부 `a op= b` → `a = a op b` 로 폅니다. `++`/`--` 도 마찬가지로 `+ 1` / `- 1` 로 폅니다 (앞에 붙이든 뒤에 붙이든 같습니다 — **값을 돌려주지 않는 문장**이라 차이가 없습니다).

### 4.2 식과 우선순위

낮은 것부터 높은 것 차례입니다. 따로 적지 않으면 **왼쪽부터** 묶입니다.

| 단계 | 연산자 | 묶는 방향 |
|---|---|---|
| 1 | `or` `\|\|` | 왼쪽 |
| 1.5 | `??` | 왼쪽 |
| 2 | `and` `&&` | 왼쪽 |
| 3 | `==` `!=` | 왼쪽 |
| 4 | `<` `>` `<=` `>=` `in` `not in` | 왼쪽 |
| 5 | `\|` | 왼쪽 |
| 6 | `^` | 왼쪽 |
| 7 | `&` | 왼쪽 |
| 8 | `<<` `>>` | 왼쪽 |
| 9 | `+` `-` | 왼쪽 |
| 10 | `*` `/` `%` | 왼쪽 |
| 11 | `-` `not` `!` `~` (앞에 붙는 것) | 오른쪽 |
| 12 | `**` | **오른쪽** |
| 13 | `f(...)` `x[i]` `x[a:b]` `a.b` `a.b(...)` `a?.b` `a?.b(...)` | 왼쪽 |

> **눈여겨볼 것 두 가지.**
>
> **비트 연산(`\| ^ & << >>`)이 비교보다 높습니다.** C 와 다릅니다 — 그리고 이쪽이 사람이 기대하는 대로입니다.
> `a & b == c` 는 `(a & b) == c` 입니다. (C 라면 `a & (b == c)` 가 되어 괄호를 꼭 쳐야 합니다.)
> `a \| b < c` 도 마찬가지로 `(a \| b) < c` 입니다.
>
> **`**` 는 앞에 붙는 `-` 보다 높습니다.** `-2 ** 2` 는 `-(2 ** 2)` 즉 `-4` 입니다. 그리고 `**` 는 오른쪽부터 묶여서 `2 ** 3 ** 2` 는 `2 ** (3 ** 2)` 즉 512 입니다.

```ebnf
primary = NUMBER | STRING | fstring
        | "true" | "false" | "none" | "this" | "super"
        | "print" call_args
        | lambda
        | IDENT [ call_args ]
        | "(" [ expression { "," expression } [ "," ] ] ")"      (* 괄호 묶기 / 튜플 *)
        | "[" [ list_body ] "]"
        | "{" [ dict_body ] "}"
        | "forr" "(" for_part "," expression "," for_part ")"

lambda    = "func" [ IDENT { "," IDENT } ] ":" expression
list_body = expression ( { "," expression } [ "," ] | comp_tail )
dict_body = expression ":" expression ( { "," expression ":" expression } [ "," ] | comp_tail )
comp_tail = "for" IDENT "in" expression [ "if" expression ]

call_args = "(" [ call_arg { "," call_arg } ] ")"
call_arg  = IDENT "=" expression            (* 이름 붙인 인자 *)
          | [ expression ] ":" [ expression ]   (* 구간 — upper(0:5, 말) *)
          | expression
```

- `()` 는 **빈 튜플**입니다. `(1)` 은 그냥 `1` 이고, 원소 하나짜리 튜플은 `(1,)` 입니다.
- 리스트·딕셔너리·튜플·인자 목록 모두 **끝에 쉼표를 하나 더 붙여도 됩니다.**
- 이름 없는 함수(`lambda`)의 몸통은 **식 하나**뿐입니다.
- `x[]` 처럼 비워 두는 것은 오류입니다. `x[:]`, `x[a:]`, `x[:b]` 는 됩니다.
- `forr(...)` 은 식 자리에서 쓰는 반복이며, 첫 칸은 **반드시 `val` 선언**이어야 합니다.
- 이름 없는 함수의 매개변수에는 **기본값을 적을 수 없습니다** (이름 있는 함수에는 됩니다).

## 5. 시맨틱 (Semantics)

### 5.1 값의 갈래

| 갈래 | 설명 |
|---|---|
| `none` | 값 없음 |
| `bool` | `true` / `false` |
| `int` | 부호 있는 64 비트 정수 |
| `float` | IEEE 754 배정밀도 |
| `str` | 코드포인트 배열 (고칠 수 없음) |
| `bytes` | 바이트 배열 |
| `list` | 늘었다 줄었다 하는 배열 (고칠 수 있음) |
| `tuple` | 고칠 수 없는 배열 |
| `dict` | **넣은 차례를 지키는** 해시 표 |
| `func` | 함수 (닫힘 환경을 들고 다닙니다) |
| `class` `instance` `bound` `super` | 객체지향 쪽 |
| `module` | `bring` 이 만들어 주는 것 |
| `file` | `open` 이 돌려주는 것 |
| `error` | `catch` 가 잡아 주는 것 |
| `task` | `start` 가 돌려주는 **따로 도는 일감** (5.13) |

### 5.2 이름 찾기 순서 — **가장 중요한 규칙**

`이름(...)` 꼴로 부를 때 찾는 차례는 이렇습니다.

1. **내장 함수** — `lumiwords.h` 에 있는 이름
2. 지금 환경에서 위로 올라가며 찾은 값 (내가 만든 함수·클래스·변수)

**내장이 먼저입니다.** 그래서 `func sort(...)` 를 만들고 `sort(x)` 를 부르면 **내 것이 아니라 내장이 돕니다.** 오류도 안 납니다. 이것이 이 언어에서 가장 조용히 틀리는 자리라, `lumi lint` 의 첫 번째 규칙이 이것입니다.

빠져나갈 길 두 가지:
- **메서드는 이 규칙을 안 탑니다.** 클래스 안의 `func add(...)` 는 `x.add(...)` 로 불리므로 멀쩡합니다.
- **모듈 이름을 거치면 안전합니다.** 라이브러리의 `func pow(...)` 는 `math.pow(2, 3)` 으로만 불리므로 가려지지 않습니다.

이름을 **값으로 읽을 때**(`f` 처럼 괄호 없이)는 내장을 보지 않고 환경만 봅니다.

### 5.3 변수와 유효 범위

- `val x = v` — **지금 환경에** 새로 만듭니다. 같은 자리에 또 만들면 덮어씁니다.
- `x = v` — 이미 있는 것을 고칩니다. 위로 올라가며 찾고 **없으면 오류**입니다 (`NameError`).
- `global x = v` — 맨 바깥(전역) 환경에 만듭니다.
- `local x = v` — 지금 환경에 만듭니다. **`val` 과 똑같이 돕니다** (7.4 절의 정할 것 목록에 있습니다).
- 함수는 만들어질 때의 환경을 **닫아서 들고 다닙니다**(클로저).
- 자료형을 적어 선언한 변수는 그 자료형을 **기억합니다.** 나중에 `x = v` 로 고칠 때 그 자료형으로 맞춰집니다.

**어떤 블록이 자기 환경을 갖는지는 갈립니다.** 들여쓴다고 다 새 환경이 되는 것이 아닙니다.

| 새 환경을 만드는 것 | 만들지 않는 것 (바깥 환경을 그대로 씁니다) |
|---|---|
| 함수 몸통 | `if` / `elif` / `else` |
| `for` 몸통 — **한 바퀴마다 새로** | `while` 몸통 |
| `forr(...)` | `switch` 의 `case` / `default` 몸통 |
| `use` 몸통 | `try` / `safe` / `always` 몸통 |
| `catch` 가 잡은 변수 | |
| `test` 몸통 | |
| 클래스의 공유 값 | |

```
if true:
    val 안쪽 = 1
print(안쪽)          // 1 — if 는 새 환경을 만들지 않으므로 보입니다

for i in [1, 2]:
    val 한바퀴 = i
// 한바퀴 는 여기서 안 보입니다 — for 는 한 바퀴마다 새 환경입니다
```

`for` 가 한 바퀴마다 새 환경을 쓰는 것은 **클로저 때문입니다.** 반복 안에서 만든 함수들이 마지막 값 하나를 같이 보지 않고, 각자 그 바퀴의 값을 붙듭니다.

호출 깊이는 `LUMI_MAX_DEPTH`(2000)까지입니다. 넘으면 오류입니다.

### 5.4 참과 거짓

`if`, `while`, `and`, `or`, `not` 이 보는 기준입니다.

| 값 | 거짓일 때 |
|---|---|
| `none` | 언제나 거짓 |
| `bool` | `false` |
| `int` / `float` | 0 |
| `str` | 빈 글자 |
| `list` / `tuple` / `dict` / `bytes` | 비어 있을 때 |
| 그 밖 (함수·객체·파일 …) | **언제나 참** |

### 5.5 같음, 그리고 딕셔너리 키 동일성

- `==` 는 값끼리 견줍니다. 숫자는 `int` 와 `float` 을 섞어 견줄 수 있습니다 (`1 == 1.0` 은 참).
- **딕셔너리 키는 다릅니다. 값과 갈래가 둘 다 같아야 같은 키입니다.**

```
val d = {1: "정수", true: "참"}
len(d)        // 2 — 1 과 true 는 다른 키입니다
1 == true     // 참 — 하지만 키로서는 다릅니다
```

이것은 **일부러 정한 규칙**입니다. `1` 과 `true` 가 같은 칸에 들어가면 딕셔너리에 무엇을 넣었는지 알 수 없게 되기 때문입니다. (파이썬은 반대로 합니다.)

### 5.6 숫자

- **정수 넘침을 검사합니다.** `+ - * **` 가 64 비트를 넘으면 조용히 감기지 않고 `MathError` 를 냅니다.
- 정수끼리 `/` 는 나누어떨어지지 않으면 실수를 줍니다.
- 0 으로 나누면 `MathError` 입니다.
- `int` 와 `float` 이 섞이면 `float` 으로 올려서 셈합니다.

### 5.7 자리 세기와 자르기

- 자리는 **0 부터**입니다.
- **음수 자리는 뒤에서부터**입니다. `-1` 이 마지막입니다.
- `x[a:b]` 는 `a` 이상 `b` 미만입니다. 양쪽 다 생략할 수 있습니다.
- 자르기는 **범위를 벗어나도 오류가 아닙니다** — 있는 만큼만 줍니다. 하지만 `x[i]` 로 하나를 꺼낼 때 범위를 벗어나면 `IndexError` 입니다.
- 없는 키를 꺼내면 `KeyError` 입니다.

### 5.8 함수 호출

인자를 맞추는 차례입니다.

1. 이름 없이 준 인자를 **앞에서부터** 매개변수에 채웁니다.
2. 이름 붙인 인자(`f(칸 = 3)`)를 그 이름 자리에 넣습니다. 이미 찬 자리면 오류입니다.
3. 아직 빈 자리는 **기본값**으로 채웁니다.
4. 그래도 빈 자리가 있으면 `ArgumentError` 입니다.

- **기본값은 부를 때마다 새로 셈합니다** (함수를 만들 때 한 번이 아닙니다). 그래서 `func f(xs = [])` 가 파이썬처럼 값을 물고 있지 않습니다.
- 기본값 식은 **함수가 만들어진 환경**에서 셈합니다.
- 인자는 **왼쪽부터** 차례로 셈합니다.
- 값을 바로 부를 수 있습니다: `목록[0](10)`, `바깥(5)(3)`.

### 5.9 클래스

- `class 자식 from 부모:` 로 물려받습니다. 한 부모만 됩니다.
- 메서드를 찾을 때는 자기 클래스부터 부모 쪽으로 올라갑니다.
- `this` 는 그 객체, `super` 는 부모 쪽에서 찾기 시작하라는 뜻입니다.
- `abstract func` 는 몸통이 없고, 물려받은 쪽에서 채워야 합니다.
- 연산자 재정의: `add` `sub` `mul` `div` `mod` `lt` `gt` `get` `set` 메서드를 만들면 `+ - * / % < > [] []=` 가 그리로 갑니다.
- **반복자**: `iter()` 가 리스트를 돌려주거나, `iter()`/`next()` 짝을 만들면 `for x in 내객체:` 가 됩니다. `iter()` 가 리스트가 아닌 것을 주면 `TypeError` 입니다.

### 5.10 오류

오류 종류는 이렇게 이어져 있습니다. `catch 부모` 는 자식도 잡습니다.

```
Error
├── LookupError
│   ├── IndexError
│   └── KeyError
├── FileError
│   └── FileNotFound
├── TypeError
├── ValueError
├── NameError
├── MathError
├── ArgumentError
├── NetworkError
├── DatabaseError
└── AssertError
```

`error("내가지은종류", "말")` 로 아무 이름이나 낼 수 있습니다. 표에 없는 이름은 부모가 `Error` 입니다.

- `catch` 는 **앞에서부터 처음 맞는 하나만** 돕니다.
- `safe` 는 **오류가 안 났을 때만** 돕니다.
- `always` 는 **언제나** 돕니다 (오류가 났든 안 났든, `return` 으로 빠져나가든).
- 잡힌 오류 값은 `e.type` `e.message` `e.line` `e.file` 을 갖습니다.
- 아무도 안 잡으면 프로그램이 멈추고 **호출 자취**(파일:줄)를 함께 찍습니다.

### 5.11 모듈 (`bring`)

찾는 차례입니다. 먼저 맞는 것을 씁니다.

1. 지금 파일이 있는 폴더의 `이름.lumi`
2. 그 폴더의 `lumi_packages/이름/` (`lumi.json` 의 `main`, 없으면 `main.lumi` → `index.lumi` → `이름.lumi`)
3. `~/.lumi/packages/` 에서 같은 방식으로
4. `lumi` 실행 파일 옆(그리고 위로 세 단계까지)의 `libraries/`

- `bring "폴더/파일"` 처럼 **따옴표로 적으면 경로**입니다. `.lumi` 는 생략할 수 있습니다.
- 담기는 이름은 `bring 이름 = "경로"` 로 고를 수 있고, 안 고르면 파일 이름입니다.
- `bring 무엇 up 이것, 저것` 은 골라서 **지금 이름 자리에 바로** 놓습니다 (이러면 5.2 의 가려짐 문제가 생길 수 있습니다).
- **같은 파일은 한 번만 읽습니다.** 두 번째부터는 먼저 만든 것을 그대로 씁니다.
- 모듈을 읽을 때 도는 것은 `func` · `class` · `val` · `bring` 뿐입니다. 그 밖의 문장은 돌지 않습니다.

### 5.12 `test` 블록

`test "이름":` 은 **`lumi test` 로 돌릴 때만** 돕니다. 그냥 파일을 돌리면 조용히 건너뜁니다. 시험 하나에서 난 오류는 그 시험만 실패로 적고 다음으로 넘어갑니다.

### 5.13 따로 도는 일감 (`start` / `wait`)

내장 함수 둘뿐입니다. 새 문법은 없습니다.

```
start(부를것, 값, ...)   -> task
wait(task)              -> 그 함수가 돌려준 값
```

- `start` 는 **부를 수 있는 값**(내가 만든 함수, 이름 없는 함수, 클래스)만 받습니다. 아니면 `TypeError` 입니다. 나머지 인자는 그대로 넘어갑니다.
- 일감은 **실 하나**에 태워집니다. 시작할 때 인자를 그 자리에서 세어 들고, 끝나면 돌려준 값을 들고 있습니다.
- `wait` 은 그 일감이 끝날 때까지 기다린 뒤 값을 돌려줍니다. **같은 일감을 여러 번 기다려도** 됩니다 — 두 번째부터는 이미 들고 있는 값을 그대로 줍니다.
- 일감 안에서 난 오류는 그 자리에서 뜨지 않고 **`wait` 을 부른 자리에서 다시 납니다.** 종류(`e.type`)와 말(`e.message`)이 그대로 살아 있어서 `catch ValueError e:` 로 골라 잡을 수 있습니다.
- 아무도 `wait` 하지 않은 일감은, 그 값이 사라질 때 끝날 때까지 기다렸다가 치웁니다 (놓친 실이 남지 않습니다).

**한 번에 하나만 돕니다 (큰 자물쇠).** 참조 세기와 순환 수집기가 안전하려면 Lumi 코드가 한 번에 한 실에서만 돌아야 합니다. 그래서 **자리를 내주는 곳은 `sleep` 과 `shell` 둘뿐**입니다 (`bring http` 는 `shell` 로 curl 을 부르므로 여기 들어옵니다).

이 규칙에서 따라오는 것:

| 그래서 | 뜻 |
|---|---|
| 기다리는 일은 **겹칩니다** | 파일 열둘을 내려받거나 셸 명령 여럿을 돌릴 때 빨라집니다 |
| 셈만 하는 일은 **안 겹칩니다** | 계산을 나눠 돌린다고 빨라지지 않습니다 |
| `sleep`·`shell` 사이의 줄들은 **끊기지 않습니다** | 그래서 자물쇠(mutex) 같은 것이 따로 필요 없습니다 |
| 전역 변수는 **함께** 씁니다 | 일감마다 제 지역 자리와 제 오류 자리를 갖지만, `globals` 는 하나입니다 |

**`gc()` 는 일감이 도는 동안 부르지 마세요.** 순환 수집기는 한 줄기로 도는 것을 전제로 합니다.

## 6. 실행 모델

- **트리워크 인터프리터**입니다. 소스 → 토큰 → AST 로 만든 뒤 **그 트리를 따라가며 바로 실행**합니다. 바이트코드로 옮기는 단계는 없습니다.
- 메모리는 **참조 세기**로 관리하고, 서로 붙들고 도는 것은 **순환 수집기**가 거둡니다 (`gc()` 로 부를 수도 있습니다).
- 오류는 `setjmp`/`longjmp` 로 위로 올라갑니다. 오류 자리(`lumi_err_*`, `lumi_jmp`)는 **실마다 따로**입니다.
- 실은 `start` 로 띄울 수 있지만, **큰 자물쇠 하나**가 한 번에 한 실만 Lumi 코드를 돌게 합니다 (5.13). 자리를 내주는 곳은 `sleep` 과 `shell` 뿐입니다.
- 운영체제마다 다른 것은 전부 `src/platform.c` 의 `plat_*` 뒤에 있습니다.

## 7. 버전 정책 (Versioning Policy)

### 7.1 지금은 0.x 입니다 — 무엇을 뜻하나

**`0.9.0` 인 동안 Lumi 의 문법과 시맨틱은 바뀔 수 있습니다.** 하위 호환을 약속하지 않습니다.

솔직히 적어 둡니다. 최근에만 해도 이런 것들이 바뀌었습니다.

- `bring` 의 경로 문법을 새로 넣었습니다 (`bring "models/user"`)
- 딕셔너리 키 동일성 규칙을 되돌렸습니다 (`1` 과 `true` 가 다시 다른 키)
- 내장 함수 이름을 바꿨습니다 (`run` → `shell`)
- 미완성 바이트코드 VM 을 걷어냈습니다

그리고 앞으로도 **점진적 정적 타입**(4 단계)이 들어오면 선언 문법이 또 움직입니다. 이런 상황에서 `1.0` 을 붙이고 호환을 약속하면 다음 주에 그 약속을 깨게 됩니다. 그래서 **약속하지 않는 쪽을 골랐습니다.**

**대신 0.x 에서도 지키는 것 하나**: 깨는 변경을 하면 반드시 **`docs/Lumi_Changes.md` 에 적습니다** — 무엇이 어떻게 바뀌었고, 예전 코드를 어떻게 고치면 되는지. 조용히 바꾸지 않습니다.

### 7.2 판 번호 읽는 법

`주.부.수` (`MAJOR.MINOR.PATCH`)

| 자리 | 언제 올리나 |
|---|---|
| **수** (patch) | 고침만. 문법·시맨틱 그대로 |
| **부** (minor) | 기능 추가. 0.x 에서는 **깨는 변경도 여기서** 납니다 |
| **주** (major) | `1.0` 부터 — 깨는 변경 |

판 번호는 `c-interpreter/src/lumi.h` 의 **`LUMI_VERSION` 한 곳**에만 적습니다. `lumi -v` 와 언어 서버가 그것을 그대로 씁니다.

### 7.3 `1.0` 이 되면 켜지는 약속

`1.0` 을 붙이는 순간부터 아래가 **약속**이 됩니다. 지금은 아직 아닙니다.

**깨지 않겠다고 약속하는 것**

1. 이 문서 2~5 장에 적힌 **문법과 시맨틱**
2. **내장 함수의 이름과 인자 차례** (`lumiwords.h`)
3. **오류 종류의 갈래** — 부모를 잡으면 자식이 잡히는 관계
4. `bring` 이 모듈을 찾는 **차례**
5. CLI 의 **명령 이름과 종료 코드** (`lumi test`/`lint`/`fmt --check` 가 실패에 1 을 주는 것)
6. `lumi.json` 과 `lumi.lock` 의 **모양**

**약속하지 않는 것** (1.0 뒤에도 바뀔 수 있습니다)

1. **오류 메시지의 글월** — 뜻은 그대로지만 문장은 다듬어집니다. 메시지 글자를 견주는 코드를 쓰지 마세요. `e.type` 을 보세요.
2. **호출 자취의 모양**
3. 언어 서버가 주고받는 것 중 **LSP 규격 밖의 것**
4. **`lumi fmt` 가 내놓는 모양** — 규칙이 나아지면 결과가 달라집니다. CI 에 걸 때는 `fmt --check` 를 **판 번호를 고정해서** 쓰세요.
5. **성능**, 그리고 값이 사라지는 정확한 시점
6. `c-interpreter/src/` 의 **C 함수와 자료구조** — 이것은 내부입니다

### 7.4 `1.0` 이 되기 전에 정해야 할 것

이것들이 정해지지 않은 채로는 호환을 약속할 수 없습니다.

- [ ] **점진적 정적 타입** — 지금 `int x = 5` 는 실행할 때 맞춰 보는 것뿐입니다. 컴파일 때 검사하기로 하면 선언 문법이 움직입니다.
- [ ] **가변 인자** (`func f(...것들):`) — 문법을 정해야 합니다.
- [ ] **`local` 의 자리** — 지금은 `val` 과 똑같이 돕니다. 남길지 없앨지 정해야 합니다.
- [ ] **`eval` 안에서 난 오류의 줄 번호** — 지금은 그 글자 안에서 센 번호가 나옵니다.
- [ ] **동시성** — 스레드를 넣으면 5.3 의 유효 범위 규칙에 손대야 할 수 있습니다.

## 8. 이 명세가 구현과 맞는지 어떻게 아나

이 문서에서 **기계가 검사할 수 있는 부분**은 검사합니다.

- **예약어 37 개** — `tests/lang/spec_test.lumi` 가 이 목록의 낱말을 변수 이름으로 써 보고 전부 막히는지 봅니다.
- **연산자 우선순위 표** — 같은 파일이 표의 각 단계를 실제 셈으로 확인합니다 (`-2 ** 2 == -4`, `a & b == c` 가 `a & (b == c)` 인 것 등).
- **오류 갈래** — 자식을 내고 부모로 잡히는지 확인합니다.
- **키 동일성**, **정수 넘침**, **자르기 규칙** — 모두 시험에 있습니다.

나머지(산문으로 적은 시맨틱)는 사람이 지켜야 합니다. **언어를 고치면 이 문서도 같이 고치세요** — 그러지 않으면 이 문서는 몇 달 뒤에 거짓말이 됩니다.
