# Lumi 바뀐 것들 (Changes)

지금은 **0.x** 입니다 — 문법과 시맨틱이 아직 바뀔 수 있습니다. 대신 **깨는 변경은 반드시 여기에 적습니다.** 무엇이 어떻게 바뀌었고, 예전 코드를 어떻게 고치면 되는지까지.

규칙은 [`Lumi_Language_Spec.md` 7 장](Lumi_Language_Spec.md#7-버전-정책-versioning-policy) 에 있습니다.

| 표시 | 뜻 |
|---|---|
| 💥 | **깨는 변경** — 예전 코드를 고쳐야 합니다 |
| ✨ | 새로 생긴 것 |
| 🔧 | 고침 (예전 코드는 그대로 돕니다) |

## 0.9.1 — 2026-08-10

### ✨ 새로 생긴 것 — 편집기에서 정의로 가기 · 쓴 곳 찾기 · 이름 바꾸기

`lumi lsp` 가 세 가지를 더 합니다. 파일이 늘어나면 grep 으로 항해하게 되던 것을 없앱니다.

| | 키 | 무엇 |
|---|---|---|
| 정의로 가기 | F12 | `func` · `class` · `val` · 매개변수 · `for`/`catch`/`use` 의 이름 · `bring ... up` 으로 들여온 이름 |
| 쓴 곳 모두 | Shift+F12 | 그 파일 안에서 그 이름이 나오는 자리 전부 |
| 이름 바꾸기 | F2 | **만드는 자리가 딱 하나일 때만** |

**이름 바꾸기가 조심스러운 까닭**: 자리(scope)를 따지지 않고 이름으로 찾습니다. 그래서 같은 이름을 만드는 곳이 둘 이상이면 — 함수 둘이 각각 `x` 라는 매개변수를 쓰는 흔한 경우 — **거절합니다.** 엉뚱한 곳까지 바꾸느니 안 바꾸는 편이 낫습니다. 함수·클래스·전역처럼 만드는 자리가 하나인 이름은 그대로 바뀝니다. 편집기는 `prepareRename` 으로 미리 알아채 F2 자체를 막아 줍니다.

자리를 찾는 데 AST 가 아니라 **토큰**을 씁니다 — AST 노드는 줄만 알고 칸을 모르는데, 편집기에 자리를 짚어 주려면 칸이 있어야 하기 때문입니다.

시험: `tests/lsp/` — 디버거와 같은 방식으로, 짜 둔 LSP 대화를 `lumi lsp` 에 흘려 넣고 답을 바이트로 견줍니다 (거절해야 하는 두 경우까지). **언어 서버에 시험이 하나도 없었습니다** — 이번에 처음 생겼습니다.

### ✨ 새로 생긴 것 — `lumi lint` 가 오타와 인자 개수를 잡습니다

예전에는 이런 파일이 **"nothing to worry about"** 이었습니다.

```lumi
func f(x):
    return x + 1

func g():
    val y = undefined_thing(3)   // 없는 함수
    val z = f(1, 2, 3)           // f 는 인자 하나
    return typo_var + 1          // 없는 변수
```

셋 다 같은 파일 안에서 알 수 있는 것인데 실행해서 그 줄에 닿아야만 났습니다. 드물게 도는 갈래에 숨어 있으면 배포 뒤에야 터집니다. 규칙 둘을 더했습니다.

**L8 — 인자 개수.** 모자람 · 남음 · 없는 이름 · 두 번 준 것 · 이름 붙인 인자 뒤에 그냥 인자. 규칙은 `interp.c` 의 `invoke_function_kw` 를 그대로 옮겼습니다.

**L9 — 이 파일 어디에도 없는 이름.** 값을 읽는 자리(`print(x)`), 부르는 자리(`x()`), 그리고 `val` 없이 담는 자리(`x = 1` — 실행하면 NameError 입니다) 셋을 봅니다.

**거짓 경고를 내지 않는 것을 가장 앞에 두었습니다.** 이름은 자리(scope)를 따지지 않고 파일 한 자루에 모읍니다 — 자리를 따지면 잡을 수 있는 것이 늘지만 멀쩡한 코드를 나무라기 시작합니다. `bring "경로"` 로 이름이 들어오는 파일에서는 L9 를 아예 끕니다. 같은 이름에 값이 담긴 적이 있으면(`func f` 뒤에 `val f = ...`) 그 함수는 L7·L8 에서 빠집니다. 예제 62 개 · 라이브러리 4 개 · 시험 파일 15 개에서 **거짓 경고 0 개**를 확인했습니다.

찾는 김에 `lumiwords.h` 의 빠진 낱말 일곱을 채웠습니다 — `gc` `isdir` `json` `json_parse` `json_stringify` `file` `dir`. 이 표는 편집기 자동완성과 IDE 색칠이 함께 쓰는 **한 곳뿐인 목록**인데, 여기 없어서 자동완성에도 안 뜨고 있었습니다. (L9 를 켜자마자 이것들이 오타로 잡혀서 알게 됐습니다.)

### 🔧 고침 — 웹서버가 인터프리터를 얼리던 것

**`http.serve` 를 띄우면 그 순간 인터프리터 전체가 멈췄습니다.** 손님을 기다리는 `accept` 를 **큰 자물쇠를 쥔 채** 불렀기 때문입니다. 서버를 일감으로 띄워 두고 본 실에서 다른 일을 하려고 하면, 본 실은 한 줄도 못 돌았습니다 (12 초를 기다려도 그대로였습니다).

이제 **운영체제를 기다리는 동안에는 자물쇠를 놓습니다** — 손님 기다리기(`accept`), 자료 받기(`recv`), 답 보내기(`send`) 셋 다. `sleep`·`shell` 이 예전부터 하던 것과 같은 방식이고, 그 규칙을 매크로 두 개(`GIL_RELEASE`/`GIL_ACQUIRE`)로 한 곳에 적어 두었습니다.

```
val job = start(server)      // 서버를 일감으로 띄우고
sleep(0.3)
for val i = 0, i < 200000, i++:   // 본 실은 그동안 제 일을 합니다
    sum = sum + i
```

**아직 요청은 차례로 처리합니다** (한 번에 하나). 바뀐 것은 "서버가 도는 동안 다른 것도 돌 수 있다" 이지, "요청을 동시에 처리한다" 가 아닙니다.

시험: `tests/http/solo.lumi` — 서버와 손님을 **한 프로그램 안에서** 돌립니다. 기존 `client.lumi`/`server.lumi` 는 두 프로그램이라 이 문제를 잡지 못했습니다.

### 🔧 고침 — 순환 수집기

**세 가지가 한꺼번에 잘못돼 있었습니다.** 하나씩 고쳤고, `tests/lang/gc_test.lumi` 가 넷을 지킵니다.

**1) `gc()` 가 살아 있는 값을 치웠습니다.** 이것이 제일 큽니다.

```
val xs = [[1], [2], [3]]
print(gc())      // 3    <- 전역에 담아 둔 값을 셋이나 치웠습니다
print(xs)        // [[], [], []]
```

까닭은 `gc_restore_reachable` 이 **'이미 훑었는가'를 `gc_refs > 0` 으로 갈음**한 것이었습니다. 밖에서 붙들려 있는 값은 처음부터 `gc_refs` 가 0 이 아니라서 '이미 봤다'로 읽혔고, 그래서 **그 속에 든 값들을 한 번도 안 훑고** 지나갔습니다. 속에 든 값은 아무도 안 쓰는 값으로 보여 치워졌습니다. 이제 표시(`gc_visited`)를 따로 둡니다.

**2) 실행 중인 함수의 지역 값이 뿌리가 아니었습니다.** 수집기는 전역만 뿌리로 삼았습니다. 그래서 함수가 도는 도중에 `gc()` 가 돌면 그 함수의 지역 값이 사라졌습니다.

```
func work():
    val items = [1, 2, 3]
    val d = {"a": items}
    gc()
    print(d["a"])      // 예전: KeyError
```

이제 지금 열려 있는 이름 자리를 사슬(`ScopeGuard`)로 엮어 두고 전부 뿌리로 삼습니다 — 함수의 지역 자리, `for` 한 바퀴의 자리, `catch` 자리, `use` 자리까지. 일감(`start`)마다의 인터프리터도 사슬로 엮어 함께 훑습니다.

**3) 아무도 안 치웠습니다.** 사람이 `gc()` 를 부르기 전에는 순환 참조가 영영 남았습니다. 오래 도는 프로그램(서버·IDE)에는 그냥 새는 것이었습니다.

```
순환 100 만 개 만들기 (gc() 를 안 부름):   795.5 MB  ->  12.9 MB
```

이제 문장 사이에서 셈을 보고 문턱(2만 개)을 넘으면 저절로 한 번 돕니다. 문턱은 **만든 그릇 − 없앤 그릇**이라, 순환이 없는 프로그램에서는 이 수가 안 늘고 수집기도 안 돕니다. 속도는 그대로입니다 (검사가 매크로라 함수 부르는 값이 안 듭니다 — 함수로 뒀을 때는 10% 가 느려졌습니다).

`gc()` 는 그대로 있습니다. 이제 언제 불러도 안전하고, 치운 개수를 돌려줍니다.

### 🔧 고침 — 재귀 깊이

**깊은 재귀가 460 겹에서 소리 없이 죽던 것.** 오류 메시지도, 스택 트레이스도, `catch` 로 잡을 기회도 없이 프로세스가 사라졌습니다 (윈도우 `0xC00000FD`, 스택 넘침). `LUMI_MAX_DEPTH` 는 2000 이었지만 **한 번도 걸리지 못했습니다** — C 스택이 먼저 터졌기 때문입니다.

까닭은 컴파일러가 **한 함수의 스택 자리를 그 함수 안 모든 갈래의 지역 변수를 합친 크기로** 잡기 때문입니다. `eval_call` 은 갈래가 40 개라 8,536 바이트, `exec_node` 는 8,136 바이트였고, 둘 다 함수를 부를 때마다 지나가는 자리라 **재귀 한 겹마다 18KB** 가 쌓였습니다. 8MB ÷ 18KB ≈ 460.

고친 것 — 큰 갈래를 따로 떼어 냈습니다 (부르는 차례는 그대로입니다):

| | 전 | 후 |
|---|---|---|
| `eval_call` | 8,536 B | **200 B** (`eval_text_builtins` · `eval_world_builtins` · `eval_misc_builtins` 로 분리) |
| `exec_node` | 8,136 B | **1,800 B** (`exec_error_stmt` · `exec_try_stmt` · `run_catches` 로 분리) |
| **재귀 한 겹** | **18,144 B** | **3,344 B** (`try` 를 품으면 5,584 B) |

그래서 이제 **한도가 진짜로 걸립니다.** 어떤 모양이든 프로세스가 죽지 않고 `too much recursion` 오류가 납니다 — 그냥 재귀, `try` 를 품은 재귀, 내장 함수를 거치는 재귀, 메서드 재귀 넷 다 확인했습니다.

같이 고친 것:

- **오류를 `catch` 로 잡으면 깊이 셈이 어긋나던 것.** `longjmp` 로 뛰어오면 사이 함수들의 `in->depth--` 가 건너뛰어져 깊이가 부풀어 있었습니다. 이제 `try` 가 원래 깊이를 되돌립니다. (증상: 오류를 여러 번 잡고 나면 멀쩡한 재귀가 `too much recursion` 을 만났습니다.)
- **한도에 걸렸을 때 깊이를 0 으로 되돌리던 것.** 그 오류를 `catch` 로 잡으면 인터프리터가 '지금 맨 바깥' 이라고 잘못 알고, 이미 쌓인 C 스택 위로 다시 1000 겹을 파고들어 **진짜로** 스택을 터뜨렸습니다.
- 죽은 버퍼 `saved_msg[2048]` 을 지웠습니다 (채우기만 하고 아무도 읽지 않았습니다).
- `MAX_DEPTH` 가 `lumi.h` 와 `interp.c` 둘에 따로 적혀 있던 것을 하나로 합쳤습니다.

**💥 한도가 2000 에서 1000 으로 내려갑니다.** 지키지 못하는 2000 보다 지키는 1000 이 낫다는 판단입니다 (파이썬의 기본 한도도 1000 입니다). 한도는 `한도 × 한 겹 < 8MB` 로 정합니다 — `lumi.h` 의 `LUMI_MAX_DEPTH` 주석에 재는 방법까지 적어 두었습니다. 1000 겹보다 깊이 들어가야 하는 코드는 재귀를 반복문으로 바꾸세요.

속도는 함수 호출이 많은 코드에서 **5~10%** 빨라졌습니다 (`fib(28)` 0.98s → 0.92s, 호출 30 만 번 0.29s → 0.26s). 스택을 한 겹마다 18KB 씩 짚던 일이 없어진 만큼입니다 — 다만 CPython 과의 큰 격차는 이것 때문이 아니었습니다.

### 💥 깨는 변경

**`http` 의 딕셔너리 키가 영어로 바뀌었습니다.** 라이브러리 코드는 영어로 적으면서 사용자가 만지는 키만 한글로 두면 반쪽이 되므로, 0.x 인 지금 한 번에 맞췄습니다.

| 어디 | 예전 | 지금 |
|---|---|---|
| 답 (`http.get` 등) | `"코드"` `"본문"` `"머리말"` | `"code"` `"body"` `"headers"` |
| 답 (`http.getjson` · `http.postjson`) | `"자료"` | `"data"` |
| 요청 (`http.serve` 의 처리 함수) | `"방법"` `"길"` `"물음"` `"머리말"` `"본문"` | `"method"` `"path"` `"query"` `"headers"` `"body"` |
| `sqlite.open` 이 준 딕셔너리 | `"경로"` | `"path"` |

`"ok"` 는 그대로입니다.

```
// 예전
val 답 = http.get(주소)
if 답["ok"]:
    print(답["코드"], 답["본문"])

// 지금
val 답 = http.get(주소)
if 답["ok"]:
    print(답["code"], 답["body"])
```

```
// 예전
func 처리(요청):
    if 요청["길"] == "/인사":
        return {"코드": 200, "본문": "안녕"}

// 지금
func 처리(요청):
    if 요청["path"] == "/인사":
        return {"code": 200, "body": "안녕"}
```

**고치는 법**: 위 표대로 키 이름만 바꾸면 됩니다. 값의 뜻과 자료형은 하나도 안 달라졌습니다. 요청 딕셔너리는 인터프리터(`httpserve`)가 직접 만들므로 **`lumi` 를 새로 받아야** 합니다.

같이 바뀐 것 — `libraries/http.lumi` 와 `libraries/sqlite.lumi` 의 **안쪽 이름도 전부 영어**가 되었습니다 (`_임시이름` → `_tempname`, `_한줄` → `_row` 처럼). 이쪽은 `_` 로 시작하는 내부용이거나 매개변수 이름이라 부르는 쪽 코드는 안 깨집니다. 다만 `http.send(방법 = "GET", ...)` 처럼 **이름을 붙여 인자를 넘기고 있었다면** 새 이름(`method`, `body`, `url`, `headers`)으로 바꿔야 합니다.

### 🔧 고침

**CRLF 로 저장한 `.lumi` 가 안 열리던 것.** 렉서가 빈 줄을 줄바꿈 글자 하나(`\n`)로만 알아봐서, 윈도우 줄 끝(CRLF)으로 저장한 파일에서는 **블록 안의 빈 줄이 '빈 줄'로 안 보였습니다.** 그 줄의 칸 수가 0 으로 읽혀 열려 있던 블록이 통째로 닫히고, 그다음 줄에서 문법 오류가 났습니다.

```
func f():
    val a = 1
                  <- 이 빈 줄이 CRLF 면 여기서 함수가 끝나 버렸습니다
    return a
```

실제로 `libraries/sqlite.lumi` 가 이렇게 깨져 **`bring sqlite` 가 통째로 안 됐습니다.** 예제·라이브러리가 모두 LF 로 저장돼 있어서 시험이 한 번도 못 잡았습니다.

- 고친 곳: `src/lexer.c` 의 빈 줄 판정에 캐리지 리턴(\r)을 더했습니다.
- 회귀 시험: `tests/crlf/blankline.lumi` — **일부러 CRLF 로 저장한** 파일이고, `run.bat`·`run.sh` 둘 다 이것이 파싱되는지 봅니다. `.gitattributes` 의 `* -text` 가 그 줄 끝을 지켜 줍니다.
- 예전 코드는 그대로 돕니다. LF 파일의 동작은 한 글자도 안 달라집니다.

### ✨ 새로 생긴 것

- `tests/run.sh` — `run.bat` 의 POSIX 쌍둥이. 여섯 가지를 같은 차례로 검사합니다.
- `.github/workflows/ci.yml` — 인터프리터를 우분투·맥·윈도우에서, IDE 를 우분투(Qt6)에서.

### 💥 깨는 변경

**딕셔너리 키 동일성이 되돌아왔습니다** — `1` 과 `true` 는 다른 키입니다.

```
val d = {1: "정수", true: "참"}
len(d)        // 예전(잘못): 1     지금(맞음): 2
```

원래 정한 규칙이었는데 파이썬→C 다시 쓰기 과정에서 잃어버렸던 것을 되살렸습니다. `1 == true` 는 여전히 참입니다 — **값으로 견주는 것**과 **키로 쓰는 것**은 다른 규칙입니다. 딕셔너리에 숫자와 참/거짓을 섞어 키로 쓰고 있었다면 칸 수가 달라집니다.

**`run` 내장 함수가 `shell` 로 이름이 바뀌었습니다.**

```
run("dir")        ->  shell("dir")
runcode("dir")    ->  shellcode("dir")
```

`run` 은 사람들이 자기 함수 이름으로 흔히 쓰는 낱말이라, 내장으로 두면 `func run()` 이 **말없이 가려집니다** (명세 5.2). 실제로 예제 하나가 그렇게 깨졌습니다. 앞으로 새 내장 이름을 지을 때는 흔한 낱말을 피합니다.

**미완성 바이트코드 VM 을 걷어냈습니다.**

`try`/`catch` 가 VM 경로에서 아예 안 돌고 있었습니다 (오류 처리 스택이 둘로 갈려 있었습니다). 걷어내고 트리워크 하나만 남겼습니다. **속도는 같았습니다** (100 만 번 도는 반복 0.20 초 ↔ 0.20 초). 언어를 쓰는 쪽에서 달라지는 것은 `try`/`catch` 가 이제 **제대로 돈다**는 것뿐입니다.

### 🔧 고침

- **인자가 안 맞을 때 `ArgumentError` 를 냅니다.** 그전에는 갈래 표에 `ArgumentError` 를 두고도 **아무도 안 내고 있었습니다** (명세를 적다가 찾았습니다). `catch Error` 로는 예전과 똑같이 잡히므로 깨지지 않습니다. 이제 `catch ArgumentError` 로 좁혀 잡을 수 있습니다.
- **정수 넘침을 검사합니다.** `+ - * **` 가 64 비트를 넘으면 조용히 감기지 않고 `MathError` 를 냅니다.
- **한글 절대 경로에서 패키지를 못 찾던 것**을 고쳤습니다. `pkg.c` 가 플랫폼 계층을 건너뛰고 맨 `fopen` 을 쓰고 있어서, 경로에 한글이 들어가면 `lumi.json` 을 못 읽었습니다.
- **리눅스·맥에서 빌드됩니다.** 운영체제마다 다른 것은 `src/platform.c` 한 곳에 모았습니다. (IDE 는 아직 윈도우 전용입니다.)
- `shell()` 이 내놓는 글이 운영체제마다 달랐던 것을 맞췄습니다.
- HTTP 서버가 한글 주소를 못 알아듣던 것을 고쳤습니다 (퍼센트 적기를 풀어 줍니다).
- 판 번호를 적는 곳을 **`src/lumi.h` 의 `LUMI_VERSION` 한 곳**으로 모았습니다 (셋으로 흩어져 있었습니다).
